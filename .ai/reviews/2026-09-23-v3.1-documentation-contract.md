## Contract matrix

| Topic | Public statement |
|---|---|
| API surfaces | The package-root `Orb.*` API remains synchronous and compatible; structured subpaths are additive ES modules. |
| Browser baseline | Chrome/Edge 92+, Firefox 90+, Safari/iOS Safari 15.4+, Chrome for Android 92+, and Firefox for Android 90+; no bundled polyfills or legacy-browser guarantee. |
| Browser loading | UMD exposes the compatible `window.Orb` API; structured browser subpaths require a package-aware bundler until stable native/CDN ESM entries are verified. |
| Legacy inputs | Package-root calculations use `Date` and method-specific astronomy units. Valid historic inputs remain supported. |
| Structured inputs | Calculation time uses `AstroInstant`; angles use radians; states use km and km/s; durations use seconds. |
| Observer default | Omitting `observe` options selects `iau2006-2000b`, topocentric vector subtraction, and no light time, annual aberration, refraction, or metadata. |
| Observer corrections | Light time, annual aberration, and weather-dependent refraction are independent explicit options. |
| Observer omissions | Diurnal aberration, gravitational deflection, and polar motion are not implemented. |
| Events default | Rise/set uses the geometric body center and zero-radian horizon; passes use zero minimum elevation. Refraction and semidiameter are explicit. |
| Pass meaning | Optical visibility and sunlight are not computed. |
| Earth/Sun model | EPV00 is optional, declares 1900–2100 validity and approximately one-arcsecond source accuracy, and does not replace legacy defaults. |
| Planet data | Compact VSOP87A remains the default; full per-body coefficient modules are optional and outside the default UMD bundle. |
| SGP4 propagation | TLE/OMM values are SGP4 mean elements, propagation uses WGS-72, and `B*` is an SGP4 drag term. |
| Satellite geodesy | Structured TEME states use km/km-s; geodetic conversion uses WGS-84. |
| SGP4 prediction | Error depends on the element set and epoch age; no universal validity interval is claimed. |
| v2 baseline | Migration comparison is against tag `v2.4.1`; older v2 releases may differ. |
| v2 sequence | Change distribution first, validate compatible numerical results second, adopt structured APIs only where useful third. |
| Intentional v2 changes | TT evaluation, equinox-of-date precession, Sun distance unit consistency, WGS-84 observer geometry, topocentric parallax, UTC numeric `doy()`, and explicit sidereal naming. |

## Verification gate

`test/m7/docs.mjs` checks local links, English/Japanese contract tokens, staged
v2 migration content, tarball inclusion, and executable examples installed from
the exact npm tarball. The existing package suite additionally checks every
exported subpath and browser UMD loading.

Before documentation approval:

- run the complete test suite;
- rebuild and confirm committed `dist/` synchronization;
- run deterministic VSOP validation and `git diff --check`;
- inspect the packed file list and package version;
- review the English and Japanese prose for scientific meaning, not only API
  spelling.

Versioning and Node 18/20/22 clean-checkout release validation remain the
second M7 stage and must not start until the public documentation is approved.
