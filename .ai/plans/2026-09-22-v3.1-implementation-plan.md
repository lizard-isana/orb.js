# orb.js v3.1 implementation plan

Status: superseded by `2026-09-22-v3.1-implementation-plan-revised.md`

This initial draft is retained to preserve the planning history. It placed too
much emphasis on SGP4 and still treated educational source synchronization as a
possible repository concern. Do not use it as the implementation sequence.

Baseline: `v3` at `769e3ec`

Reference branch: `archive/v4-prototype` at `6646e23` (formerly
`v4-planning`)

Target release: `@lizard-isana/orb@3.1.0`

## 1. Goal

v3.1 is a correctness and maintainability release for the existing v3 API.
It should take the mature, independently useful parts of the branch now
preserved as `archive/v4-prototype` without turning v3 into the v4
architecture.

The release has four primary outcomes:

1. Harden TLE/OMM parsing and the SGP4/SDP4 boundary while preserving the
   existing `Orb.SGP4` and `Orb.Satellite` interfaces.
2. Replace fragile Kepler internals with bounded, testable numerical routines
   while preserving the v3 constructor and result shapes.
3. Finish the targeted time, frame, observer, and packaging corrections needed
   for a reliable v3 line.
4. Publish the first official npm package as `@lizard-isana/orb`, then make the
   v3.1 line eligible to become the GitHub default without erasing the v2 line.

This is not a v4 backport. The public v3 API remains recognizable and
synchronous, and optional large data must stay outside the default bundle.

## 2. Compatibility policy

### v3 API

As a minor release, v3.1 preserves the documented v3 surface:

- existing constructors and aliases, including `Orb.SGP4`, `Orb.Satellite`,
  `Orb.Kepler`, planet classes, `Orb.Observation`, and `Orb.Time`
- synchronous methods such as `xyz(date)`, `radec(date)`, `latlng(date)`, and
  `azel(date)`
- current result field names, units, and keyword strings
- CommonJS, ESM, browser UMD, and optional VSOP87A subpath loading

Internal modules may be split into pure helpers, but the public facade must
adapt their results back to v3 shapes.

### Correctness changes

Backward compatibility does not require retaining demonstrably incorrect
numbers. A numerical behavior change is allowed only when it has:

1. an external or independent reference value;
2. the old and new result recorded in a regression test or migration note;
3. an explicit statement of frame, center, time scale, unit, and tolerance.

### v2 compatibility

v3.1 does not add v2 shims. The v2 line is preserved through Git branches,
tags, releases, and versioned documentation. This keeps the v3 implementation
clear instead of mixing two major APIs in one runtime.

## 3. Existing baseline to preserve

The current v3 line already contains important work that must not be
reimplemented or regressed:

- Vallado-derived near-Earth and deep-space SGP4/SDP4 propagation core
- WGS-72 constants for propagation, TEME labeling, and GMST 1982 for TEME
- WGS-84 use for Earth geodetic results
- python-sgp4 2.27 reference vectors for near-Earth, GEO, Molniya, and
  GPS-like cases
- Alpha-5 catalog-number decoding
- UTC, TT, leap-second, GAST, and GMST 1982 distinctions
- TT evaluation for the ephemeris series
- explicit J2000-to-of-date conversion and the Sun/VSOP cross-check
- elliptic, parabolic, and hyperbolic public Kepler behavior
- optional per-body full VSOP87A registration without enlarging the default
  bundle
- committed `dist/` artifacts checked by CI

The implementation sequence starts by freezing these behaviors as fixtures.

## 4. What to adopt from `archive/v4-prototype`

| v4 work | v3.1 treatment | Reason |
| --- | --- | --- |
| Split TLE parsing, satellite facade, and propagation core | Adopt the separation, adapted to v3 | High value and low public-API impact |
| Vallado SGP4 propagation core | Keep the current v3 core | Already ported and reference-tested |
| TLE epoch precision tests | Adopt within JavaScript `Date`/millisecond limits | Prevent silent loss at the parser boundary |
| Universal-variable Kepler solver | Adopt behind the v3 facade after fixture comparison | Removes duplicate branches and e≈1 discontinuity |
| Reference-driven and property-style tests | Adopt | Makes numerical changes explainable |
| Educational algorithm comments with sources | Adopt for touched numerical modules | Improves auditability without runtime cost |
| Full frame graph and typed state vectors | Use as design guidance only | Too large and too disruptive for a minor release |
| New pure-function body and observer APIs | Defer to v4 | Would duplicate or replace the class API |
| Events, satellite passes, moon phases | Defer to v4 | New product scope with dependencies on the v4 model |
| Star catalogue, visible-sky API, shared vocab/meta | Defer to v4 | Large data and new output contract |
| v3 compatibility shim implemented on the v4 core | Do not import | v3.1 is the native v3 line, not a v4 wrapper |

No v4 file should be copied wholesale without checking it against current v3
fixes. In particular, the v4 TLE prototype predates v3's Alpha-5 support and
does not cover the current OMM input path.

## 5. Milestones

### M0 — Freeze the v3.1 contract and test structure

Purpose: make later numerical refactoring reviewable.

Work:

- Split the monolithic smoke coverage into domain suites while keeping one
  `npm test` entry point:
  - time and frames
  - Sun, Moon, planets, and VSOP
  - Kepler
  - TLE/OMM parsing and SGP4/SDP4
  - observer and horizontal coordinates
  - package exports
- Add a machine-readable or executable public export inventory.
- Record fixture metadata beside reference values: source, library/version,
  frame, center, time scale, unit, epoch, and tolerance.
- Test both source-level helpers and the built package. Do not let a passing
  `dist/` hide a source regression.
- Keep the current 27 smoke cases green while reorganizing; no numerical
  change belongs in M0.

Completion gate:

- Node 18, 20, and 22 pass the reorganized suite.
- `npm run build` produces no committed `dist/` difference from the intended
  source.
- CJS, ESM, UMD, and VSOP subpath exports load from a packed tarball.

### M1 — Isolate and harden TLE/OMM parsing and SGP4

Purpose: make the satellite path the first completed v3.1 improvement.

Internal structure:

- Extract pure parsing and normalization helpers from `src/orb-sgp4.js`.
- Keep `src/orb-sgp4-propagation.js` as the propagation core.
- Leave `Orb.SGP4` as the compatibility facade that exposes the existing
  `omm`, `tle`, `orbital_elements`, `sgp4`, `xyz()`, and `latlng()` members.
- Normalize TLE and OMM into one internal record before calling `sgp4init`.

Parsing requirements:

- Preserve numeric and Alpha-5 catalog numbers and verify that both TLE lines
  identify the same object.
- Preserve the 57-year pivot rule and all millisecond precision representable
  by JavaScript `Date`.
- Parse implied-decimal fields, signs, and exponents in one helper.
- Keep B* explicitly identified as the TLE/SGP4 drag term; do not describe it
  as a physical ballistic coefficient.
- Treat TLE elements as SGP4 mean elements, never as instantaneous/osculating
  Kepler elements.
- Validate required columns and finite numeric fields. Checksum enforcement
  should be opt-in or separately callable in v3.1 so existing third-party TLEs
  with bad checksums do not become an accidental breaking change.
- Preserve current OMM support, including numeric `NORAD_CAT_ID` and the stored
  user-defined TLE lines when present.

Propagation requirements:

- Keep WGS-72 for SGP4 initialization and TEME km/km/s output.
- Keep GMST 1982 for TEME-to-Earth rotation and WGS-84 for geodetic latitude,
  longitude, and altitude.
- Surface Vallado error codes as explanatory exceptions; never return a
  partially valid state.
- Avoid tuning gravity constants, operation mode, or tolerances to match an
  individual fixture.

Tests:

- Freeze the exact TLE/OMM text, epoch, package/backend version, and expected
  state for every fixture.
- Retain current near-Earth, GEO, Molniya, and GPS-like python-sgp4 2.27 cases.
- Add Alpha-5 propagation, signed exponent fields, TLE/OMM equivalence,
  line-number mismatch, object-number mismatch, malformed columns, and
  propagation error cases.
- Add TEME → geographic and observer integration cases, clearly separating
  WGS-72 propagation from WGS-84 geodesy.

Completion gate:

- Current valid inputs produce the same state within the existing reference
  tolerance.
- Every intended parser rejection has a stable error type and message.
- `Orb.SGP4` and `Orb.Satellite` public contract tests show no unintended API
  difference.

### M2 — Replace fragile Kepler internals

Purpose: remove duplicated and unbounded numerical code without changing the
v3 calling convention.

Work:

- Remove the duplicate `EllipticalOrbit` definition.
- Stop adding fallback functions to the global `Math` object; use local
  helpers or the supported native functions.
- Validate required elements, finite values, eccentricity, distance, and `gm`
  before iteration.
- Introduce bounded convergence with a clear error on failure.
- Evaluate the v4 universal-variable solver as the shared internal path for
  ellipse, parabola, and hyperbola. Keep the existing per-conic implementation
  available only during fixture comparison, then remove it if equivalence and
  near-parabolic behavior are satisfactory.
- Preserve the v3 element names, AU/AU-per-day convention, result objects, and
  `KeplerianToCartesian` / `CartesianToKeplerian` aliases.
- Define stable conventions for circular and equatorial singularities in the
  Cartesian-to-elements path and document them.

Tests:

- circular, eccentric elliptical, e just below 1, exactly parabolic, e just
  above 1, and hyperbolic cases
- forward/backward propagation and zero elapsed time
- energy and angular-momentum invariants
- elements → state → elements round trips, including circular/equatorial
  conventions
- comparison to current v3 outputs where the old solver is valid

Completion gate:

- No global mutation and no duplicate class members remain.
- Every solver has a bounded iteration count.
- Differences from v3 are either below the declared tolerance or documented
  as a correctness fix with an independent reference.

### M3 — Targeted time, frame, and observer corrections

Purpose: finish known v3 correctness work without importing the v4 frame graph.

Work:

- Preserve the established policy: ephemeris theories use TT; Earth rotation
  uses UTC as the current UT1 approximation; TEME uses GMST 1982; apparent
  places use GAST.
- Remove the `orb-time` / `orb-obliquity` circular dependency by moving pure
  shared calculations to a lower-level helper.
- Keep J2000, of-date, ecliptic, equatorial, heliocentric, and geocentric steps
  explicit in internal helper names and tests.
- Correct the observer geodetic-to-rectangular formula to the standard WGS-84
  `(N+h) cos(phi)` and `(N(1-e^2)+h) sin(phi)` form.
- Define the atmospheric-refraction validity range. Preserve the current v3
  behavior of returning a refraction field rather than silently applying it.
- Normalize metadata at input boundaries enough to give explanatory errors for
  missing or unsupported coordinate/unit keywords; do not replace v3 keyword
  strings with v4 typed state objects.

Tests:

- retain the current VSOP/Sun, Meeus, TT, GAST, GMST 1982, and J2000/of-date
  regressions
- coordinate round trips and known epoch transforms
- WGS-84 equator, pole, sea level, and elevated-observer references
- horizon, below-horizon, and invalid refraction inputs
- equivalent instance, RA/Dec, rectangular, Moon-parallax, and satellite
  observation paths

Completion gate:

- The build no longer reports the time/obliquity circular dependency.
- All changed numbers have fixture metadata and migration notes.
- Unsupported input fails explicitly rather than becoming `NaN` or a unit
  mismatch.

### M4 — Package, documentation, and release candidate

Purpose: turn the verified source into the first official npm release.

Package work:

- Keep the package name `@lizard-isana/orb` and `publishConfig.access=public`.
- Keep the project/repository name `orb.js` and browser global `Orb`.
- Exclude build-time raw VSOP JSON from the npm tarball when the generated
  per-body modules are sufficient; verify that all exported subpaths remain.
- Add package-consumer tests that install the exact tarball into a temporary
  project and exercise CommonJS, ESM, and one optional VSOP body.
- Record tarball file count, compressed size, and unpacked size. The release
  must not exceed the current measured baseline of 42 files, 3.2 MB packed,
  and 11.1 MB unpacked without a documented reason.

Documentation work:

- Update English and Japanese usage together.
- Add a v3.0 → v3.1 migration section covering numerical corrections,
  deprecated behavior, and the scoped npm import name.
- Add a satellite note stating TEME/WGS-72/WGS-84 conventions, TLE mean-element
  semantics, B* semantics, and expected prediction limits.
- Add a Kepler note describing supported conics, units, convergence failure,
  and singular-case conventions.
- Keep v2 documentation accessible from the v2 branch/tag; do not make v3.1
  docs pretend to describe v2.

Release-candidate gate:

- All tests pass on Node 18/20/22.
- `npm run build`, `git diff --check`, and committed-`dist/` synchronization
  pass from a clean checkout.
- `npm pack --dry-run` and temporary-consumer tests pass.
- The version is changed to `3.1.0` only after the release commit is otherwise
  ready.
- Publish the exact verified `3.1.0` artifact under the npm `next` dist-tag;
  do not publish from a dirty worktree.
- Verify installation and CDN loading before moving the same version from
  `next` to `latest`.

## 6. Proposed implementation sequence

Use small checkpoints with numerical changes separated from structural and
documentation-only changes:

1. `test: establish v3.1 domain and package baselines`
2. `refactor: isolate TLE and OMM parsing`
3. `test: expand SGP4 parser and Vallado reference coverage`
4. `refactor: harden Kepler propagation internals`
5. `fix: correct WGS-84 observer conversion and input validation`
6. `refactor: remove time and obliquity circular dependency`
7. `chore: reduce and verify npm package contents`
8. `docs: document v3.1 numerical and package migration`
9. `release: prepare @lizard-isana/orb 3.1.0`

Each checkpoint must pass the tests relevant to its domain, the complete test
suite, a build, `git diff --check`, and the committed-`dist/` check.

## 7. Branch and release transition

The default-branch change is a release-administration step, not part of the
numerical implementation commits.

After `3.1.0` has passed the `next` verification period:

1. Preserve the current v2 default line under an explicit `v2` branch and its
   existing tags/releases.
2. Keep `master` available as a frozen historical v2 branch unless there is a
   separate decision to retire or redirect it.
3. Create or update `main` from the verified v3.1 release commit.
4. Change the GitHub default branch to `main`.
5. Keep `v3` as the v3 maintenance branch.
6. Keep `archive/v4-prototype` explicitly reference-only.
7. Promote `@lizard-isana/orb@3.1.0` from `next` to `latest` only after the
   branch, documentation, npm install, and CDN links all resolve as intended.

Repository branch changes, GitHub default-branch changes, npm publication, and
dist-tag promotion each require their own explicit checkpoint and verification.

## 8. Out of scope for v3.1

- replacing public v3 objects with the v4 typed-state/frame-graph API
- async position methods or implicit network loading
- events, satellite-pass prediction, rise/set, or phase search APIs
- star and constellation catalogues
- self-describing v4 meta/vocabulary output
- TypeScript rewrite or a project-wide format conversion
- full JPL-grade ephemerides
- v2 compatibility shims inside the v3 runtime
- publishing `archive/v4-prototype` artifacts to npm `latest`

These exclusions keep v3.1 reviewable and leave architectural experiments on
the branch where they can evolve without constraining the stable package.

## 9. Final definition of done

v3.1 is complete when all of the following are true:

- the scoped package, documentation, and tarball use `@lizard-isana/orb`;
- public v3 contract tests show no unintended API removal;
- SGP4/TLE/OMM, Kepler, time/frame, and observer gates above pass;
- external reference fixtures explain every intentional numerical change;
- source and committed `dist/` are synchronized;
- package-consumer tests pass from the exact release tarball;
- the clean release commit is tagged and published under `next`;
- npm installation and CDN loading are verified;
- migration notes and preserved v2 documentation are available;
- promotion to `latest` and the GitHub default-branch switch are performed only
  after separate explicit approval.
