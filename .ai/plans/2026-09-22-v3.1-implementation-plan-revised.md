# orb.js v3.1 implementation plan — revised

Status: current approved direction, M0 implementation in progress

Baseline: `v3` at `0a51b6c`

Reference branch: `v4-planning` at `6646e23`

Target release: `@lizard-isana/orb@3.1.0`

## 1. Goal

v3.1 is a bridge between the established v3 API and the mature calculation
work explored on `v4-planning`.

It has two deliberately separate surfaces:

1. The existing top-level v3 API remains synchronous and compatible while
   receiving independently verified correctness fixes.
2. New calculation facilities are added through explicit, tree-shakeable
   subpaths instead of replacing the v3 classes.

The release is broader than an SGP4 refactor. It establishes reusable time,
frame, geodetic, state-vector, solver, observer, and event foundations. SGP4 is
one important consumer of those foundations rather than the organizing center
of the release.

Educational publishing is not part of v3.1. The decision and boundary are
recorded in `../decisions/2026-09-22-separate-educational-materials.md`.

## 2. Compatibility and package policy

### Existing v3 surface

The default import preserves the documented v3 API:

- constructors and aliases such as `Orb.Time`, `Orb.Kepler`, `Orb.SGP4`,
  `Orb.Satellite`, planet classes, and `Orb.Observation`
- synchronous methods such as `xyz(date)`, `radec(date)`, `latlng(date)`, and
  `azel(date)`
- current result field names, units, and keyword strings
- CommonJS, ESM, and browser UMD loading
- optional full VSOP87A registration and body subpaths

Correctness does not require preserving demonstrably wrong numbers. Every
intentional numerical change needs an independent reference or invariant, a
before/after record, and explicit frame, center, time-scale, unit, and
tolerance metadata.

### New subpath surface

The proposed additive modules are:

```text
@lizard-isana/orb/time
@lizard-isana/orb/frames
@lizard-isana/orb/geodesy
@lizard-isana/orb/kepler
@lizard-isana/orb/observer
@lizard-isana/orb/events
@lizard-isana/orb/vocab
@lizard-isana/orb/models/earth-epv00
```

New modules use structured inputs, radians and km internally, and ESM as their
primary format. They must not be imported by the legacy UMD entry unless its
facade actually needs them, so unused optional models and events do not enlarge
the default browser bundle.

Node 18 support must be tested explicitly. If source modules are exported
directly, their ESM interpretation must not depend on Node 22 syntax detection;
use a nested module boundary or generated `.mjs`/ESM output.

### v2 line

v3.1 does not include v2 runtime shims. v2 compatibility is maintained through
branches, tags, releases, and versioned documentation.

## 3. Current baseline to preserve

The v3 baseline already includes:

- Vallado-derived SGP4/SDP4 propagation with near-Earth and deep-space cases
- WGS-72 propagation constants, TEME output, and GMST 1982 rotation
- WGS-84 geodetic output
- python-sgp4 2.27 reference vectors
- Alpha-5 catalogue-number decoding
- leap-second, UTC/TT, GAST, and GMST 1982 distinctions
- TT evaluation of ephemeris series
- explicit J2000-to-of-date conversion and a Sun/VSOP cross-check
- elliptic, parabolic, and hyperbolic Kepler behavior
- optional per-body full VSOP87A registration
- committed `dist/` artifacts checked by CI

These behaviors are frozen as fixtures before structural work begins.

## 4. Scope taken from `v4-planning`

| v4 work | v3.1 treatment |
| --- | --- |
| Horizons, ERFA, Meeus, Vallado, and python-sgp4 references | Adopt with complete fixture metadata |
| Coordinate round trips and orbital invariants | Adopt as property-style tests |

No v4 file is copied wholesale without checking it against fixes made later on
the v3 branch.

## 5. Milestones

### M0 — Evidence, generation, and performance foundation

Purpose: establish the evidence needed to change numerical code safely without
changing public APIs.

Split the current smoke coverage into domain suites while retaining one
`npm test` command:

- time and reference frames
- Sun, Moon, planets, and VSOP
- Kepler and Cartesian/element conversions
- TLE/OMM and SGP4/SDP4
- observer and horizontal coordinates
- package exports and tarball consumers

Keep all current 27 smoke cases green during reorganization.

Every external fixture records its original source and version, generation or
query procedure, instant and time scale, frame and center, units, expected
accuracy class, and test tolerance.

Adopt or adapt these references:

- JPL Horizons topocentric apparent RA/Dec, azimuth/elevation, and range for
  Moon, Sun, and Mars at several instants
- ERFA/SOFA-derived nutation, obliquity, precession, and matrix values
- Meeus examples for sidereal time and lunar position
- Vallado and python-sgp4 near-Earth and deep-space vectors
- independent RK4 comparisons and two-body invariants for Kepler propagation

Horizons fixtures may initially record the legacy residual rather than impose
the modern observer tolerance. The strict tolerance becomes a gate in M3.

Property-style coverage includes:

- vector and matrix inverse/orthogonality
- frame-transform round trips and path consistency
- geodetic/ECEF round trips
- two-body energy and angular-momentum conservation
- forward/backward propagation
- element/state round trips with explicit singular-case conventions

Engineering tools:

- Add a benchmark comparing legacy and new paths where equivalent. Use it to
  detect order-of-magnitude regressions, not as a strict CI timer.
- Adapt the VSOP87A compiler to vendored primary data, deterministic generated
  modules, precision-preserving output, and compile-time truncation checks.
- Keep raw generation inputs out of the published npm tarball.

Completion gate:

- Node 18, 20, and 22 pass the reorganized suite.
- Reference provenance is stored with fixtures.
- Benchmark and VSOP verification tools run reproducibly.
- M0 introduces no runtime numerical change.

### M1 — Additive time, vector, frame, vocabulary, and geodetic core

Purpose: introduce the common structured substrate without replacing v3
objects.

#### Time

Add `Instant` through `@lizard-isana/orb/time` with construction from `Date`,
ISO, Unix milliseconds, and one- or two-part JD; two-part TT storage; explicit
`jd('utc'|'ut1'|'tt')`; and immutable time arithmetic.

Legacy `Orb.Time` remains public and delegates only after equivalence tests.

#### Frames

Add vector/matrix primitives and structured state vectors through
`@lizard-isana/orb/frames`:

```js
{
  t: Instant,
  frame: 'ecliptic-j2000',
  center: 'sun',
  r: Float64Array,
  v: Float64Array | null
}
```

Internal units are km, km/s, and radians. Unknown frames and unsupported paths
throw instead of being guessed from strings.

Initial graph edges cover ecliptic/equatorial J2000, mean/true equatorial of
date, TEME, ECEF, and observer ENU/horizontal frames.

#### Geodesy

Add pure WGS-84 geodetic/ECEF/ENU functions through
`@lizard-isana/orb/geodesy`. After reference tests pass, the legacy observer
may reuse them.

#### Vocabulary

Add controlled quantity, unit, frame, center, correction, effect, and source
names through `@lizard-isana/orb/vocab`. Legacy `coordinate_keywords` and
`unit_keywords` remain accepted and unchanged.

Completion gate:

- ERFA/Meeus frame references pass at declared tolerances.
- Round-trip and unknown-path tests pass.
- New subpaths load on Node 18/20/22.
- Legacy top-level exports remain unchanged.

### M2 — Solvers, reproducible ephemerides, and optional Earth/Sun models

Purpose: add modern numerical models on top of M1 without changing legacy
defaults.

#### Universal-variable Kepler

Expose through `@lizard-isana/orb/kepler`:

- `propagateKepler(r0, v0, dt, mu)`
- `elementsToState(elements, mu)`
- `stateToElements(state, mu)`

Require one bounded propagation path for all conics, continuity through
`e = 1`, finite and physical input validation, explicit non-convergence
failure, defined singular-case conventions, and no global `Math` mutation.

After independent and legacy comparisons pass, connect existing `Orb.Kepler`
methods through an AU/AU-per-day adapter. Preserve legacy method names and
result shapes.

#### VSOP87A generation

- Generate or verify coefficients from vendored official VSOP87A data.
- Preserve current short-table defaults and optional full registration until a
  separately verified model switch is approved.
- Record input checksums, term counts, validity interval, and worst truncation
  error.

#### Optional EPV00 Earth and derived Sun

Expose EPV00 through a model subpath or new structured body, not as a silent
legacy default. The corresponding Sun is the negated Earth state so both share
one theory.

#### Body/state adapter

Define the minimal body contract:

```js
body.state(instant) -> structured state
```

Provide adapters for existing v3 planets, Moon, Sun, Kepler, and SGP4 objects
so later modules can consume legacy instances without duplicating theories.

Completion gate:

- Vallado, RK4, invariant, time-reversal, and near-parabolic tests pass.
- Legacy Kepler differences are within tolerance or documented as fixes.
- VSOP generation is deterministic and self-validating.
- EPV00 and derived Sun pass ERFA/Horizons references.
- Optional models do not enter the default bundle.

### M3 — Explicit modern observer and accuracy options

Purpose: combine M1/M2 into a coherent optional apparent-place pipeline rather
than scattering unrelated flags through legacy functions.

Add `@lizard-isana/orb/observer` with:

- IAU 2006 precession and IAU 2000B nutation
- separately selectable light-time iteration and annual aberration
- diurnal parallax through common-frame vector subtraction
- optional refraction using supplied pressure and temperature
- optional structured meta

Example direction:

```js
site.observe(body, instant, {
  frameModel: 'iau2006-2000b',
  lightTime: true,
  aberration: true,
  refraction: { pressure: 1010, temperature: 10 },
  meta: true
});
```

Compatibility rules:

- legacy `Observation.azel(date)` keeps its default behavior
- legacy opt-in uses a new options argument or named method
- refraction is not applied unless requested
- structured meta is off by default for legacy calls

Meta identifies quantity, unit, frame, center, corrections, source, accuracy,
and ignored effects. It does not generate prose or recommendations.

Completion gate:

- Horizons Moon/Sun/Mars topocentric fixtures pass their model tolerances.
- Geometric and apparent options have measured, documented differences.
- Range, geocentric distance, RA/Dec, and azimuth/elevation stay distinct.
- Invalid model combinations fail explicitly.

### M4 — Events as additive modules

Purpose: add useful high-level calculations that exercise the complete new
pipeline without changing legacy classes.

Add `@lizard-isana/orb/events` with shared bounded search primitives and:

- rise, set, and transit
- lunar elongation, principal phases, and age
- satellite passes with configurable minimum elevation

Requirements:

- searches operate on `Instant`
- event definitions state whether elevation is geometric or refracted
- horizon constants and semidiameter conventions are documented
- step and refinement tolerances are configurable and bounded
- geometric satellite passes do not imply optical visibility or sunlight

Completion gate:

- event ordering and threshold re-evaluation properties pass.
- phase times agree with an independent reference.
- pass prediction passes fixed TLE/site fixtures.
- importing events does not enlarge the default entry.

### M5 — SGP4/TLE/OMM integration and hardening

Purpose: connect the mature propagation core to M1 and complete parser
hardening.

Work:

- Extract pure TLE and OMM parsing/normalization from `src/orb-sgp4.js`.
- Preserve `Orb.SGP4`, `Orb.Satellite`, `omm`, `tle`, `orbital_elements`,
  `xyz()`, and `latlng()`.
- Add a structured satellite state tagged TEME/earth/km/km-s.
- Use M1 `Instant`, TEME→ECEF, and WGS-84 in the additive path.
- Preserve numeric and Alpha-5 catalogue numbers.
- Verify both TLE lines identify the same object.
- Parse signed implied-decimal fields in one helper.
- Preserve OMM and stored user-defined TLE lines.
- Keep checksum enforcement opt-in or separately callable.
- Keep WGS-72 for propagation and WGS-84 for geodesy.
- Label TLE data as SGP4 mean elements and B* as the SGP4 drag term, not a
  physical ballistic coefficient.

Tests retain near-Earth, GEO, Molniya, and GPS-like python-sgp4 vectors and add
Alpha-5 propagation, TLE/OMM equivalence, malformed input, object mismatch,
epoch precision, propagation errors, frame conversion, observer integration,
and pass prediction.

Completion gate:

- Valid legacy inputs preserve current vectors at existing tolerance.
- Parser failures have stable explanatory errors.
- Legacy SGP4 contracts show no unintended API change.
- Structured satellites work with M3 observer and M4 passes.

### M6 — Legacy adapters, package, documentation, and release

Purpose: ship a verified dual-surface package.

Legacy integration:

- Correct legacy WGS-84 observer conversion through the tested M1 helper.
- Remove the time/obliquity circular dependency.
- Turn unsupported coordinate/unit inputs into explanatory errors where this
  does not reject valid historical inputs.
- Keep numerical and format-only changes in separate checkpoints.

Package verification:

- Use `@lizard-isana/orb` with public access.
- Keep project name `orb.js` and browser global `Orb`.
- Exclude raw build inputs and unexported generation data from the tarball.
- Test the exact tarball in temporary consumers: legacy CJS/ESM/UMD, optional
  full VSOP, and every documented new subpath.
- Record file count, packed and unpacked size, and default-bundle size.

Documentation:

- Update English and Japanese usage together.
- Add v3.0→v3.1 migration notes and scoped npm imports.
- Document legacy versus structured APIs, models, frames, time scales, units,
  accuracy, and ignored effects.
- Document SGP4 TEME/WGS-72/WGS-84, mean-element, B*, and prediction limits.
- Keep educational chapters, exercises, annotated source, and teaching demos
  outside this repository.

Release gate:

- Tests pass on Node 18/20/22 from a clean checkout.
- Build, committed-`dist/` synchronization, and `git diff --check` pass.
- Generation tools reproduce committed generated files.
- Tarball consumer and CDN tests pass.
- Change version to `3.1.0` only when otherwise release-ready.
- Publish the exact verified artifact under npm `next`, then move the same
  version to `latest` only after installation and CDN verification.

## 6. Proposed checkpoint sequence

1. `test: establish v3.1 references and domain suites`
2. `tooling: add benchmark and reproducible VSOP validation`
3. `feat: add Instant and vector primitives as subpaths`
4. `feat: add explicit frame and WGS-84 transforms`
5. `feat: add shared vocabulary for structured APIs`
6. `feat: add universal-variable Kepler functions`
7. `refactor: connect legacy Kepler through verified adapters`
8. `feat: add optional EPV00 Earth and derived Sun`
9. `feat: add explicit apparent observer pipeline`
10. `feat: add structured observation metadata as an option`
11. `feat: add rise-set, phase, and pass events subpath`
12. `refactor: isolate TLE and OMM parsing`
13. `refactor: connect SGP4 to structured time and frames`
14. `fix: apply verified legacy observer and input corrections`
15. `chore: verify package subpaths and reduce tarball inputs`
16. `docs: document v3.1 APIs, models, and migration`
17. `release: prepare @lizard-isana/orb 3.1.0`

Every numerical checkpoint runs its domain tests, the full suite, build,
`git diff --check`, and committed-`dist/` verification. Generated artifacts
are reviewed separately from handwritten numerical changes.

## 7. Branch and release transition

After `3.1.0` passes the npm `next` verification period:

1. Preserve the current v2 line under an explicit `v2` branch and existing
   tags/releases.
2. Keep `master` as a frozen historical v2 branch unless separately retired.
3. Create or update `main` from the verified v3.1 release commit.
4. Change the GitHub default branch to `main`.
5. Keep `v3` as the v3 maintenance branch.
6. Keep `v4-planning` experimental and do not publish it as `latest`.
7. Promote `@lizard-isana/orb@3.1.0` from `next` to `latest` only after branch,
   documentation, install, and CDN checks pass.

Branch changes, default-branch changes, npm publication, and dist-tag promotion
remain separate explicit checkpoints.

## 8. Out of scope

- removing or replacing the public v3 class API
- async position methods or implicit network loading
- optional full data in the default bundle
- changing legacy defaults without references and migration notes
- full JPL-grade ephemerides
- v2 runtime shims inside v3
- TypeScript rewrite or project-wide format conversion
- making the star/constellation catalogue a release requirement
- educational chapters, exercises, staged teaching implementations,
  source-excerpt synchronization, annotated source, or educational CI
- publishing `v4-planning` directly to npm `latest`

## 9. Definition of done

v3.1 is complete when:

- legacy contract tests show no unintended API removal;
- new subpaths load independently without enlarging the default bundle;
- reference and property tests explain every numerical change;
- generation tools are deterministic and their inputs have provenance;
- optional EPV00, apparent corrections, meta, and events pass their gates;
- SGP4/TLE/OMM and Kepler pass without tuning constants to fixtures;
- source, generated data, and committed `dist/` are synchronized;
- the exact tarball passes legacy and new-subpath consumer tests;
- migration and model-selection docs exist in English and Japanese;
- the clean release commit is tagged and published under `next`;
- npm install and CDN loading are verified;
- `latest` promotion and default-branch switching require separate approval;
- no educational build or synchronization responsibility remains in orb.js.

## 10. Implementation progress

M0 started on 2026-09-22 with a runtime-neutral test reorganization:

- the original 27 smoke cases are split into time/frame, ephemeris, Kepler,
  SGP4, and observer suites;
- `npm test` remains the single full-suite command;
- `test/smoke.js` remains as a compatibility entry point;
- the required provenance fields for numerical fixtures are documented under
  `test/fixtures/`.

The next M0 step is to move the inline Meeus, Horizons, JPL, and python-sgp4
reference values into provenance-bearing fixtures, then add property and
package-consumer suites without changing runtime calculations.
