## 1. Goal

v3.1 is a bridge between the established v3 API and the mature calculation
work explored on `v4-planning`.

It has two deliberately separate surfaces:

1. The existing top-level v3 API remains synchronous and compatible while
   receiving independently verified correctness fixes.
2. New calculation facilities are added through explicit, tree-shakeable
   subpaths instead of replacing the v3 classes.

The release is broader than an SGP4 refactor. It establishes reusable time,
frame, geodetic, state-vector, solver, observer, and event foundations. SGP4 is
one important consumer of those foundations rather than the organizing center
of the release.

Educational publishing is not part of v3.1. The decision and boundary are
recorded in `../decisions/2026-09-22-separate-educational-materials.md`.

## 2. Compatibility and package policy

### Existing v3 surface

The default import preserves the documented v3 API:

- constructors and aliases such as `Orb.Time`, `Orb.Kepler`, `Orb.SGP4`,
  `Orb.Satellite`, planet classes, and `Orb.Observation`
- synchronous methods such as `xyz(date)`, `radec(date)`, `latlng(date)`, and
  `azel(date)`
- current result field names, units, and keyword strings
- CommonJS, ESM, and browser UMD loading
- optional full VSOP87A registration and body subpaths

Correctness does not require preserving demonstrably wrong numbers. Every
intentional numerical change needs an independent reference or invariant, a
before/after record, and explicit frame, center, time-scale, unit, and
tolerance metadata.

### New subpath surface

The proposed additive modules are:

```text
@lizard-isana/orb/time
@lizard-isana/orb/frames
@lizard-isana/orb/geodesy
@lizard-isana/orb/kepler
@lizard-isana/orb/observer
@lizard-isana/orb/events
@lizard-isana/orb/sgp4
@lizard-isana/orb/vocab
@lizard-isana/orb/models/earth-epv00
```

New modules use structured inputs, radians and km internally, and ESM as their
primary format. They must not be imported by the legacy UMD entry unless its
facade actually needs them, so unused optional models and events do not enlarge
the default browser bundle.

Node 18 support must be tested explicitly. If source modules are exported
directly, their ESM interpretation must not depend on Node 22 syntax detection;
use a nested module boundary or generated `.mjs`/ESM output.

### v2 line

v3.1 does not include v2 runtime shims. v2 compatibility is maintained through
branches, tags, releases, and versioned documentation.

### M1 — Additive time, vector, frame, vocabulary, and geodetic core

Purpose: introduce the common structured substrate without replacing v3
objects.

#### Time

Add `Instant` through `@lizard-isana/orb/time` with construction from `Date`,
ISO, Unix milliseconds, and one- or two-part JD; two-part TT storage; explicit
`jd('utc'|'ut1'|'tt')`; and immutable time arithmetic.

Legacy `Orb.Time` remains public and delegates only after equivalence tests.

#### Frames

Add vector/matrix primitives and structured state vectors through
`@lizard-isana/orb/frames`:

```js
{
  t: Instant,
  frame: 'ecliptic-j2000',
  center: 'sun',
  r: Float64Array,
  v: Float64Array | null
}
```

Internal units are km, km/s, and radians. Unknown frames and unsupported paths
throw instead of being guessed from strings.

Initial graph edges cover ecliptic/equatorial J2000, mean/true equatorial of
date, TEME, ECEF, and observer ENU/horizontal frames.

#### Geodesy

Add pure WGS-84 geodetic/ECEF/ENU functions through
`@lizard-isana/orb/geodesy`. After reference tests pass, the legacy observer
may reuse them.

#### Vocabulary

Add controlled quantity, unit, frame, center, correction, effect, and source
names through `@lizard-isana/orb/vocab`. Legacy `coordinate_keywords` and
`unit_keywords` remain accepted and unchanged.

Completion gate:

- ERFA/Meeus frame references pass at declared tolerances.
- Round-trip and unknown-path tests pass.
- New subpaths load on Node 18/20/22.
- Legacy top-level exports remain unchanged.

### M2 — Solvers, reproducible ephemerides, and optional Earth/Sun models

Purpose: add modern numerical models on top of M1 without changing legacy
defaults.

#### Universal-variable Kepler

Expose through `@lizard-isana/orb/kepler`:

- `propagateKepler(r0, v0, dt, mu)`
- `elementsToState(elements, mu)`
- `stateToElements(state, mu)`

Require one bounded propagation path for all conics, continuity through
`e = 1`, finite and physical input validation, explicit non-convergence
failure, defined singular-case conventions, and no global `Math` mutation.

After independent and legacy comparisons pass, connect existing `Orb.Kepler`
methods through an AU/AU-per-day adapter. Preserve legacy method names and
result shapes.

#### VSOP87A generation

- Generate or verify coefficients from vendored official VSOP87A data.
- Preserve current short-table defaults and optional full registration until a
  separately verified model switch is approved.
- Record input checksums, term counts, validity interval, and worst truncation
  error.

#### Optional EPV00 Earth and derived Sun

Expose EPV00 through a model subpath or new structured body, not as a silent
legacy default. The corresponding Sun is the negated Earth state so both share
one theory.

#### Body/state adapter

Define the minimal body contract:

```js
body.state(instant) -> structured state
```

Provide adapters for existing v3 planets, Moon, Sun, Kepler, and SGP4 objects
so later modules can consume legacy instances without duplicating theories.

Completion gate:

- Vallado, RK4, invariant, time-reversal, and near-parabolic tests pass.
- Legacy Kepler differences are within tolerance or documented as fixes.
- VSOP generation is deterministic and self-validating.
- EPV00 and derived Sun pass ERFA/Horizons references.
- Optional models do not enter the default bundle.

### M3 — Explicit modern observer and accuracy options

Purpose: combine M1/M2 into a coherent optional apparent-place pipeline rather
than scattering unrelated flags through legacy functions.

Add `@lizard-isana/orb/observer` with:

- IAU 2006 precession and IAU 2000B nutation
- separately selectable light-time iteration and annual aberration
- diurnal parallax through common-frame vector subtraction
- optional refraction using supplied pressure and temperature
- optional structured meta

Example direction:

```js
site.observe(body, instant, {
  frameModel: 'iau2006-2000b',
  lightTime: true,
  aberration: true,
  refraction: { pressure: 1010, temperature: 10 },
  meta: true
});
```

The third argument is optional. Omitting it is exactly equivalent to the
following explicit geometric, airless configuration:

```js
site.observe(body, instant, {
  frameModel: 'iau2006-2000b',
  lightTime: false,
  aberration: false,
  refraction: false,
  meta: false
});
```

This default always uses the modern frame model and topocentric vector
subtraction, but it does not choose apparent-place or atmospheric corrections
on the caller's behalf. Light time, annual aberration, refraction, and
structured metadata are independently and explicitly enabled. The structured
observer boundary uses radians and km; refraction conditions use hPa and
degrees Celsius.

Compatibility rules:

- legacy `Observation.azel(date)` keeps its default behavior
- legacy opt-in uses a new options argument or named method
- refraction is not applied unless requested
- structured meta is off by default for legacy calls

Meta identifies quantity, unit, frame, center, corrections, source, accuracy,
and ignored effects. It does not generate prose or recommendations.

Completion gate:

- Horizons Moon/Sun/Mars topocentric fixtures pass their model tolerances.
- Geometric and apparent options have measured, documented differences.
- Range, geocentric distance, RA/Dec, and azimuth/elevation stay distinct.
- Invalid model combinations fail explicitly.

### M4 — Events as additive modules

Purpose: add useful high-level calculations that exercise the complete new
pipeline without changing legacy classes.

Add `@lizard-isana/orb/events` with shared bounded search primitives and:

- rise, set, and transit
- lunar elongation, principal phases, and age
- satellite passes with configurable minimum elevation

Requirements:

- searches operate on `Instant`
- event definitions state whether elevation is geometric or refracted
- horizon constants and semidiameter conventions are documented
- step and refinement tolerances are configurable and bounded
- geometric satellite passes do not imply optical visibility or sunlight

The M4 default contract follows M3: omitted options use geometric positions
without atmospheric refraction. Rise/set uses a zero-radian geometric horizon
and the body center (`semidiameter: 0`); satellite passes use a zero-radian
minimum elevation. Callers opt into refraction through `observation.refraction`
and opt into upper-limb or conventional horizons through explicit values.
`HORIZON_CONSTANTS` publishes mean solar/lunar semidiameters, standard horizon
refraction, and combined conventional center elevations, but none is selected
automatically. A combined constant must not be used together with the same
explicit refraction or semidiameter correction.

Public results and options use radians, km, and `Instant`. Rise/set and pass
results label elevation as `geometric` or `refracted`; pass results also label
optical visibility and sunlight as `not-computed`. Shared searches cap steps at
one day, tolerance at one hour, iterations at 128, and evaluations at one
million. Rise/set further caps sampling steps at six hours and satellite pass
searches at five minutes so a caller cannot silently select an obviously
inappropriate coarse grid.

Completion gate:

- event ordering and threshold re-evaluation properties pass.
- phase times agree with an independent reference.
- pass prediction passes fixed TLE/site fixtures.
- importing events does not enlarge the default entry.

Local completion evidence (2026-09-23): all four gates pass in
`test/m4/core.mjs` and the exact-tarball package suite. The configured Node
18/20/22 CI matrix remains pending until push.

## 7. Branch and release transition

After `3.1.0` passes the npm `next` verification period:

1. Preserve the current v2 line under an explicit `v2` branch and existing
   tags/releases.
2. Keep `master` as a frozen historical v2 branch unless separately retired.

remain separate explicit checkpoints.

## 8. Out of scope

- removing or replacing the public v3 class API
- async position methods or implicit network loading
- optional full data in the default bundle
- changing legacy defaults without references and migration notes
- full JPL-grade ephemerides
- v2 runtime shims inside v3
- TypeScript rewrite or project-wide format conversion
- making the star/constellation catalogue a release requirement

## 9. Definition of done

v3.1 is complete when:

- legacy contract tests show no unintended API removal;
- new subpaths load independently without enlarging the default bundle;
- reference and property tests explain every numerical change;
- generation tools are deterministic and their inputs have provenance;
- optional EPV00, apparent corrections, meta, and events pass their gates;
- SGP4/TLE/OMM and Kepler pass without tuning constants to fixtures;
- source, generated data, and committed `dist/` are synchronized;
- the exact tarball passes legacy and new-subpath consumer tests;
- migration and model-selection docs exist in English and Japanese;
- the clean release commit is tagged and published under `next`;
- npm install and CDN loading are verified;
- `latest` promotion and default-branch switching require separate approval;
- no educational build or synchronization responsibility remains in orb.js.
